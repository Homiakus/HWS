# HWS local IPC contract

Status: proposed v0 contract for the first headless/Desktop vertical slice.

## 1. Boundary

The GNOME Shell extension is a client. `hwsd` owns the well-known user-session D-Bus name and is the authoritative application/orchestration process.

```text
GNOME Shell extension
        │
        │ org.homiakus.HWS1
        ▼
       hwsd
```

The protocol is versioned independently from internal Go structs and from the Axiom model version.

## 2. D-Bus identity

Proposed constants:

```text
bus name:      org.homiakus.HWS1
object path:   /org/homiakus/HWS1
interface:     org.homiakus.HWS1
protocol:      1
```

`hwsd` must run on the user session bus. It must not require root privileges.

## 3. Handshake

The Shell client must perform `Hello` after acquiring a proxy and after every D-Bus owner change.

Request:

```text
Hello(clientProtocol: u, clientInstance: s)
```

Response fields:

```text
serverProtocol: u
serverInstance: s
revisionEpoch: s
capabilities: a{sv}
```

Rules:

1. incompatible major protocol => mutations disabled;
2. `serverInstance` changing invalidates operation assumptions tied to the previous daemon process;
3. `revisionEpoch` changing invalidates cached tree/workspace revisions;
4. after reconnect, the client fetches fresh snapshots before sending placement/window mutations.

## 4. Read methods

Initial method surface:

```text
GetTree(parentNodeID: s, knownRevision: s) -> (revision: s, nodesJson: s)
GetPath(nodeID: s, knownRevision: s) -> (revision: s, pathJson: s)
GetWorkspace(workspaceID: s) -> (revision: s, stateJson: s)
GetOperation(operationID: s) -> (stateJson: s)
GetCapabilities() -> (capabilitiesJson: s)
Search(query: s, limit: u, knownRevision: s) -> (revision: s, resultsJson: s)
```

JSON is an initial transport payload choice, not a license to leak arbitrary internal Go structures. Each payload has an explicit schema version.

## 5. Mutation methods

```text
ActivateWorkspace(workspaceID: s, definitionRevision: s, operationKey: s)
    -> (operationID: s)

RecoverWorkspace(workspaceID: s, operationKey: s)
    -> (operationID: s)

SuspendWorkspace(workspaceID: s)
    -> (operationID: s)

ResumeWorkspace(workspaceID: s, operationKey: s)
    -> (operationID: s)

CloseWorkspace(workspaceID: s, operationKey: s)
    -> (operationID: s)
```

Mutation calls acknowledge accepted intent. They do not mean that the desired desktop state has already been reached.

## 6. Operation keys

Every external-effect mutation carries an `operationKey` generated by the caller or by `hwsd` at a higher-level intent boundary.

Properties:

- stable across safe retries of the same intent;
- different for a semantically new intent;
- included in correlation logs;
- passed to the Axiom lifecycle as the activity idempotency key source.

The D-Bus reply `operationID` is an observation/tracking identifier. It is not a replacement for the idempotency key.

## 7. Signals

Proposed signals:

```text
TreeRevisionChanged(revision: s)
WorkspaceStateChanged(workspaceID: s, revision: s, stateJson: s)
OperationChanged(operationID: s, stateJson: s)
CapabilitiesChanged(revision: s)
DaemonDegrading(reasonCode: s)
```

Signals are hints to refresh/projection updates. A missed signal must not make the client permanently inconsistent; snapshot reads remain authoritative.

## 8. Timeout and cancellation

Shell must not synchronously block its UI main loop on long D-Bus calls.

Targets:

- local read calls: client timeout <= 2 s;
- mutation acceptance: client timeout <= 2 s;
- actual workspace activation may continue asynchronously and is observed through operation/workspace state;
- disconnect/cancel does not imply rollback of already executed external effects.

## 9. Error envelope

Machine-readable errors use stable reason codes, for example:

```text
protocol_incompatible
stale_revision
workspace_not_found
workspace_definition_invalid
capability_unavailable
operation_conflict
daemon_recovering
internal_error
```

Human-facing UI text is generated separately and may be localized.

## 10. Stale-state rules

A mutation that depends on a tree/workspace definition revision must either include that revision or resolve it server-side immediately before execution.

The Shell client must discard/reload cached snapshots when:

- D-Bus owner changes;
- `revisionEpoch` changes;
- protocol handshake says cached schema is unsupported;
- a response returns `stale_revision`.

## 11. Security

- user session bus only;
- no arbitrary shell command method;
- no method accepts raw secrets;
- privileged operations, if ever added, use a separate narrowly scoped boundary;
- logs redact payload fields designated sensitive by schema;
- Shell is not allowed to invoke hidden generic `Exec`/`Eval` methods.

## 12. Contract testing

Before GNOME integration is considered usable, tests must cover:

1. compatible/incompatible handshake;
2. daemon owner disappearance and reappearance;
3. stale revision rejection;
4. repeated mutation with the same operation key;
5. client timeout while server operation continues;
6. missed signal followed by snapshot recovery;
7. malformed/oversized payload rejection;
8. protocol schema round-trip fixtures.
